# AI Canvas Apple 风格 UI 改版规划

版本：1.0  
目标：只重做视觉系统、界面层级和反馈质感，不改变任何现有功能、节点逻辑或数据结构。

## 1. 改版结论

这次不把 AI Canvas 做成 macOS 系统应用的仿制品，而是采用 Apple 的设计方法：清晰、克制、直接操控、即时反馈、空间关系稳定。

最终界面气质：

- 专业桌面创作工具，而不是网页后台。
- 画布和作品是主角，工具栏退到第二层。
- 节点信息密度高，但阅读顺序清楚。
- 浮动工具使用轻透材质，节点内容使用稳定的不透明表面。
- 动画用于说明状态和空间关系，不做无意义装饰。
- 中文界面保持不变，紫色品牌色和黄/绿端口语义保持不变。

## 2. 绝对不改的功能边界

以下能力全部保留，UI 改版不得改变其逻辑或结果：

- 无限画布、点阵网格、缩放和平移方式。
- 鼠标中键拖动画布，Command/Ctrl + 滚轮缩放。
- 节点拖拽、框选、多选、复制、删除、群组、取消群组。
- 节点层级与“最后点击的节点置顶”规则。
- 图片拖入、粘贴、下载、编辑和标注。
- Prompt 编辑、复制和前置 Prompt 连接关系。
- AI 节点的模型、参数、运行、停止、成功和失败逻辑。
- 黄色文字端口、绿色图片端口和只能同色连接的规则。
- 连线方向、连接校验、自动生成输出节点的逻辑。
- 项目保存、恢复、撤销、重做和本地 API 设置。
- 现有所有节点类型、节点参数、模型名称和中文文案。
- Mac 与 Windows 的现有兼容能力。

本次允许修改的范围：

- 色彩变量、字体质感、圆角质感、描边、阴影和透明材质。
- 顶部栏、左工具栏、缩放栏、面板和节点的纯视觉外观。
- 控件的视觉状态、悬停、按下、聚焦和状态反馈。
- 不改变行为结果的过渡动画。
- 修复内容溢出时，只增加外层容器承载空间，不移动原有控件位置。

额外硬性约束：不改变任何现有功能的位置、顺序、显隐状态和操作路径；不新增、不删除任何功能。节点外框、标题栏高度和按钮尺寸只允许为清晰度做小幅优化，且不能造成旧画布重排、节点重叠、端口偏移或内容溢出。

## 3. 核心体验原则

### 3.1 安全与可预测

- 相同外观的控件必须具有相同交互。
- 删除、失败、运行中、已完成使用固定位置和固定颜色。
- 浮层从触发按钮附近出现，并沿同一路径关闭。
- 不在动画期间禁用用户输入；用户可以立即进行下一次操作。

### 3.2 直接操控

- 拖动节点时节点和指针保持一比一移动。
- 按钮在按下瞬间产生反馈，不等点击结束才反馈。
- 节点拖动时只提升阴影和轻微缩放，不改变节点尺寸。
- 连接端口在开始连线后立即突出同类型端口，弱化不同类型端口。

### 3.3 清晰优先

- 一级操作始终可见：运行、停止、模型、主要参数、节点标题。
- 低频参数按视觉分组，但不隐藏、不删除现有选项。
- 状态信息和操作按钮分离，避免标题栏拥挤。
- 所有长文本、长模型名和错误信息必须有稳定的换行或截断规则。

### 3.4 克制的层次

- 只有顶部栏、左工具栏、右侧浮层和缩放栏使用玻璃材质。
- 节点主体保持不透明，避免画布和连线透入内容区影响阅读。
- 不在玻璃表面上继续叠加玻璃表面。
- 颜色只承担品牌、端口类型、状态和危险操作四类语义。

## 4. 整体空间规划

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部浮动栏：Logo / 项目名                         撤销 / 重做 │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌────────┐                                  ┌─────────────┐ │
│  │ 左工具栏│          无限画布与节点工作流       │ 非阻塞侧面板 │ │
│  │        │                                  │ 设置/返图等  │ │
│  └────────┘                                  └─────────────┘ │
│                                                              │
│                                        ┌───────────────────┐ │
│                                        │ 缩放与画布控制栏   │ │
│                                        └───────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

空间规则：

- 顶部栏保持当前位置和功能顺序；高度与按钮尺寸只允许小幅视觉优化。
- 左工具栏保持当前位置和功能顺序；外框与按钮尺寸只允许小幅视觉优化。
- 右侧设置和返图面板保持当前位置、开关方式和字段顺序；尺寸调整不得改变操作路径。
- 编辑器、确认框等模态任务保持当前入口、位置和操作路径。
- 缩放控制保持当前右下角位置、顺序和全部现有按钮；尺寸只允许小幅视觉优化。

## 6. 分区域改版方案

### 6.1 顶部栏

保留功能：Logo、项目名称及菜单、撤销、重做、现有刷新类操作。

视觉调整：

- 保持当前高度和位置，改为轻玻璃材质层。
- 使用 `backdrop-filter: blur(20px) saturate(160%)`。
- 去掉显眼硬分割线，改用底部渐隐分隔。
- 项目名按钮使用透明底，悬停时显示轻灰圆角背景。
- 撤销/重做保持右侧位置，统一为 36px 圆形按钮。
- 禁用态通过对比度降低表达，不改变按钮位置。

对应文件：`components/layout/TopBar.tsx`、`app/globals.css`。

### 6.2 左侧工具栏

保留功能和顺序，不移动入口。

视觉调整：

- 保持当前工具栏宽度、按钮尺寸、命中区域和垂直位置。
- 工具栏使用一层中等厚度玻璃材质，避免每个按钮单独发光。
- 选中工具用品牌紫色实心圆，不额外增加大阴影。
- 悬停提示从当前按钮右侧生长，关闭时回到相同来源。
- 按下反馈为 `scale(0.96)`，在 pointer-down 立即生效。
- 删除按钮仅在可删除时变为危险色，默认保持中性。

对应文件：`components/layout/LeftToolbar.tsx`。

### 6.3 无限画布

保留全部画布手势、网格和吸附逻辑。

视觉调整：

- 背景改为柔和系统灰 `#F5F5F7`。
- 点阵网格降低对比度，避免和连线竞争。
- 画布空白处不添加渐变光斑或装饰纹理。
- 框选区域使用淡紫填充和 1px 紫色描边。
- 拖动画布时只改变光标，不给整个画布增加动画。

对应文件：`components/canvas/Canvas.tsx`、`app/globals.css`。

### 6.4 节点卡片

### 6.7 设置、返图和其他侧面板

## 7. 动效规范

### 7.1 默认反馈

| 场景 | 建议效果 |
| --- | --- |
| 按钮按下 | pointer-down 立即缩放至 0.96 |
| 节点悬停 | 阴影加深，100–140ms |
| 节点拖动 | 保持一比一跟手，轻微提升至 1.008–1.012 |
| 菜单出现 | 从触发点缩放 0.98 → 1，同时淡入 |
| 面板出现 | 临界阻尼，无弹跳，约 0.3s 响应 |
| 节点生成 | 轻微缩放与淡入，约 0.3s 响应 |
| 状态切换 | 颜色和透明度 120–180ms |
| 删除 | 先淡出并缩小至 0.98，再执行现有移除流程 |

原则：

- 普通界面动画不使用弹跳。
- 只有用户带速度释放的拖拽行为才允许轻微弹性。
- 动画只使用 `transform` 和 `opacity` 等合成友好属性。
- 用户可在动画中立即再次操作，不能锁死输入。
- 不增加循环浮动、呼吸或装饰性光效。

### 7.2 减少动态效果

```css
@media (prefers-reduced-motion: reduce) {
  /* 位移动画改为短淡入淡出，关闭弹性和循环灯带位移 */
}

@media (prefers-reduced-transparency: reduce) {
  /* 浮动玻璃层改为接近不透明背景，并关闭 backdrop-filter */
}

@media (prefers-contrast: more) {
  /* 提高文字、描边和端口对比度 */
}
```

## 8. 响应式与跨平台规则

- Mac 使用系统字体；Windows 自动回退到 `Microsoft YaHei UI` 和 `Segoe UI`。
- 不依赖 macOS 独有模糊效果；不支持 `backdrop-filter` 时使用半透明实色背景。
- 浏览器缩放和项目的显示缩放不能导致菜单超出视口。
- 低于 1280px 宽度时，侧面板不压缩节点画布内部坐标，只覆盖显示。
- 控件文本放大到 125% 时不得裁切标签、状态和运行按钮。
- 所有图标按钮保留 `aria-label` 和可见聚焦状态。

## 9. 实施顺序

### 第一阶段：设计令牌和基础状态

1. 在 `app/globals.css` 建立统一颜色、字体、圆角、阴影和动效令牌。
2. 将散落的重复颜色和阴影逐步替换为变量。
3. 补齐 hover、active、focus-visible、disabled 四种状态。
4. 不修改任何 Zustand action、节点类型和事件处理函数。

### 第二阶段：应用外壳

1. 统一顶部栏材质和尺寸。
2. 统一左工具栏的按钮、提示和按下反馈。
3. 统一右下缩放栏及其菜单。
4. 统一设置面板和返图面板的侧栏结构。

### 第三阶段：节点系统

1. 先改共享的 NodeShell、NodeHeader、NodeActions、NodeStatusBadge。
2. 再统一 BaseNode 中的输入框、下拉框、参数标签和错误提示。
3. 检查所有长节点的实际内容高度，解决控件掉出卡片问题。
4. 逐个验证图片、Prompt、导演、生成、精修和其他现有节点。

### 第四阶段：空间反馈与动画

1. 统一弹出菜单的来源位置和关闭路径。
2. 调整节点进入、拖动、复制、删除和运行状态动画。
3. 增加 reduced-motion、reduced-transparency 和高对比模式。
4. 不改变已有快捷键、手势识别和操作结果。

### 第五阶段：回归验证

1. Mac Chrome/Safari 本地运行检查。
2. Windows 11 Chrome/Edge 和 Electron 包检查。
3. 使用 100%、125%、150% 显示缩放检查面板和菜单。
4. 使用短节点、长节点、多人群组和大量连线工作区检查性能。

## 10. 验收标准

### 功能零回归

- 所有现有节点均可正常添加、运行、复制、删除和连接。
- 黄口只能连接黄口，绿口只能连接绿口。
- 中键拖动、滚轮移动、Command/Ctrl 缩放保持原样。
- 保存、恢复、撤销、重做和项目菜单保持原样。
- 所有 API 参数、模型列表和生成结果保持原样。

### 视觉一致性

- 顶部栏、工具栏、缩放栏和侧面板属于同一套材质语言。
- 所有节点标题、状态、按钮和表单控件使用统一规格。
- 页面中不再出现同类控件使用多套圆角、阴影和灰色。
- 长模型名和错误信息不会挤破布局。
- 任何菜单、下拉框和节点内容都不会掉出视口或卡片。

### 交互质感

- 按钮按下瞬间有反馈。
- 节点拖动始终跟手，不因视觉动画产生延迟。
- 面板和菜单可以在过渡中再次操作。
- 动画进入和退出路径一致。
- 开启减少动态效果后仍有清晰的状态反馈。

## 11. 明确不采用的设计

- 不做 macOS 窗口红黄绿按钮仿制。
- 不把所有节点做成半透明玻璃。
- 不使用大面积渐变、霓虹光、流光边框和循环呼吸动画。
- 不把工具栏改成带大量文字的后台导航。
- 不新增底部 Dock、标签页、全局搜索或命令面板。
- 不折叠、删除或重排现有功能入口。
- 不为了视觉改版重构节点数据、API、Store 或连线系统。

## 12. 首轮建议修改文件

首轮只做基础视觉和共享组件，风险最低：

1. `app/globals.css`
2. `components/nodes/shared/NodeShell.tsx`
3. `components/nodes/shared/NodeHeader.tsx`
4. `components/nodes/shared/NodeActions.tsx`
5. `components/nodes/shared/NodeStatusBadge.tsx`
6. `components/layout/TopBar.tsx`
7. `components/layout/LeftToolbar.tsx`
8. `components/layout/ZoomControl.tsx`

完成首轮并确认视觉方向后，再处理 `BaseNode.tsx` 中数量较多的具体节点表单，避免一次改动范围过大。
